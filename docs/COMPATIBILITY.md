# ProofX Compatibility Policy

> This document describes how ProofX handles protocol changes and proof
> format evolution. It is the authoritative reference for version
> compatibility guarantees.

## Version scheme

ProofX follows [Semantic Versioning](https://semver.org/):

- **MAJOR** — breaking protocol or proof format change that cannot be
  automatically migrated.
- **MINOR** — new features, new evidence types, new CLI commands. Backward
  compatible: existing proofs remain verifiable.
- **PATCH** — bug fixes, documentation, tooling. No protocol changes.

## Proof format versions

| Version range | Proof scheme | Signature binding | Verification |
|---------------|-------------|-------------------|-------------|
| v0.2.0 | Legacy `algo:root` binding | `sign(algo \|\| root)` | Legacy only |
| v0.2.1+ | Full commitment binding | `sign(commitment)` | Current |

### Legacy binding (v0.2.0)

The ed25519 signature was computed over:

```
"proofx/sign/v1\x00" || algorithm || "\x00" || root
```

This committed only to the Merkle root. Claims, project, subject, and
proof version were **not** cryptographically bound by the signature.

### Full commitment binding (v0.2.1+)

The ed25519 signature is computed over:

```
"proofx/sign/v1\x00" || commitmentDigest
```

where `commitmentDigest = sha256(version || project || subject || claims || algo || root)`.

This commits the signature to the **complete semantic content** of the
proof: version, project, subject, claims, algorithm, and Merkle root.

## What this means for verifiers

### v0.2.0 proofs

Proofs generated with v0.2.0 (or any pre-0.2.1 version) are:

- ✅ Valid under the legacy signing scheme
- ❌ **Rejected** by the current v0.2.1+ verifier
- 🔄 Must be **regenerated** with v0.2.1+ to be accepted

### v0.2.1+ proofs

Proofs generated with v0.2.1+ are:

- ✅ Accepted by the current verifier
- ✅ Signed with full commitment binding
- ✅ Portable across machines (no `working_dir` in evidence)

## Migration

To migrate from v0.2.0 to v0.2.1+:

```bash
# Update proofx
go install github.com/EslaM-X/proofx/cmd/proofx@v0.2.1

# Re-collect and re-prove
proofx collect
proofx prove

# Verify
proofx verify proof.json
```

The old `proof.json` will be overwritten. The new proof is signed with
the full commitment binding and will pass verification.

## Backward compatibility guarantees

1. **Proofs are forward-compatible within a major version.** A proof
   generated by v0.2.x can be verified by any v0.2.y (y >= x) verifier,
   unless a protocol change explicitly breaks this (documented in CHANGELOG).

2. **Verification is strict.** The verifier does not accept legacy proofs
   by default. There is no `--legacy` flag. Legacy proofs must be
   regenerated.

3. **No silent migration.** When a proof format changes, the old format
   is rejected with a clear error message, not silently accepted or
   migrated.

4. **Domain labels version with the protocol.** All hash steps use `v1`
   labels (e.g., `proofx/evidence/v1\x00`). A future protocol change
   would introduce `v2` labels, making old proofs structurally
   incompatible.
